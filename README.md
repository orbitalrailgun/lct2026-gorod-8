# Сервис прогнозирования инцидентов в инженерных коллекторах

Команда **«Дискреция творца»** — задача №8 «Город», ЛЦТ-2026.
Постановщик: Департамент ЖКХ Москвы. Эксплуатант: АО «Москоллектор».

---

## Идея

Сервис не выдаёт число. Он выдаёт **вердикт с обоснованием на языке диспетчера**:

> 🔴 **Объект Кси, ПК213 — отказ шлейфа, 87 % в ближайшие 24 ч**
>
> **Почему так решено:**
> 1. 74 из 75 дымовых датчиков отрезка молчат более 8 ч — вклад +38 %
> 2. Канал ДД ПК772 за 7 суток дал 240 переходов «Неисправен» при норме 3 — вклад +22 %
> 3. Отрезок непрерывен по пикетам: 57 точек из 59 — признак общего кабеля — вклад +15 %
>
> **Это НЕ пожар:** сработок дыма за сутки — 0.
> **Чего мы не видим:** тепловых датчиков на объекте нет, подтвердить температурой нечем.

Последняя строка — принципиальная. Тепловых датчиков нет на 13 объектах из 16,
датчиков затопления — на 8 из 16. Сервис, который в этих зонах скажет «риск низкий»,
обманет диспетчера. Он обязан сказать «здесь я слеп».

## Троичная логика

Состояние канала имеет три значения, а не два: **+1** отклонение, **0** неизвестно, **−1** норма.

Правило «логических доменов» заказчика записывается одной операцией — `min(t₁, t₂)`:

- `min(+1, −1) = −1` — сосед в норме, одиночную тревогу не засчитываем
- `min(+1, 0) = 0` — соседа нет → **«не знаю», а не «нет»**

в разделе 15 [пояснительной записки](docs/13-пояснительная-записка.md).

## Развёртывание

Требуется только Docker 24+ с Compose v2. Python, датасет и обучение модели
для запуска стенда **не нужны**: вердикты и геометрия лежат в образе.

```bash
git clone <адрес репозитория> concorde
cd concorde
docker compose up
```

Интерфейс поднимется на **http://localhost:8080**. Признак успешного старта
в логах — строка `загружено вердиктов: 162`.

Проверка живости:

```bash
curl http://localhost:8080/api/health
# {"status":"ok","database":true}
```

### Вход в систему

Аутентификация двухфакторная, поэтому текущий одноразовый код показывается
прямо на странице входа:

1. выбрать пользователя из списка;
2. раскрыть блок **«Код для демонстрации»** и нажать **«Показать»**;
3. ввести шестизначный код и нажать «Войти».

| Логин | Роль | Что доступно |
|---|---|---|
| `ods` | Диспетчер ОДС | всё, включая настройки и журнал аудита |
| `dispatcher` | Диспетчер района | вердикты района, решения, заявки |
| `tehnik` | Техник | просмотр по назначенным объектам |
| `brigade` | Группа реагирования | заявки и решения по назначенным объектам |

Для обзора удобнее входить как `ods`.

### Полный пересчёт на данных

Нужен только для переобучения модели или пересчёта вердиктов.
Выполняется офлайн, на машине с датасетом; достаточно 16 ГБ ОЗУ.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
unzip dataset.zip -d dataset

python -m scripts.01_build_marts        # витрины из 313 млн событий
python -m scripts.02_twins_and_domains  # тёзки и логические домены
python -m scripts.03_train_m1           # обучение и метрики
python -m scripts.04_horizon_sweep      # кривая качества по горизонтам
python -m scripts.05_generate_verdicts  # вердикты -> deploy/seed_verdicts.json
python -m scripts.09_build_analytics    # агрегаты для диаграмм
```

Перезапуска контейнера после пересчёта **недостаточно**: загрузка вердиктов
идемпотентна и пропускается при непустой таблице. Новый набор заливается явно:

```bash
docker compose exec db psql -U concorde -c "TRUNCATE verdict CASCADE;"
docker compose exec app python -m scripts.06_seed_db
```
